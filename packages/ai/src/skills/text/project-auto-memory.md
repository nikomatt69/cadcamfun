# Project memory and continuation

Use project facts already supplied in context. Call memory action recall only when relevant facts are missing or need refreshing; do not repeat memory and drawing reads before every tool. Inspect the bound drawing when its state or revision is missing/stale, not simply because a new step started.

Project notes may be shared across sessions of this project; native conversation history, todo and goal belong to this session. A note from another drawing is not current geometry. Reconcile reusable facts with the bound drawing/setup and live revisions; never reuse ids across projects. includeContext=false means automatic project context was omitted, not that a previous project's facts apply.

After successful work, use memory_edit action remember for new confirmed reusable facts: units, machine/work offset, material, workholding, named constraints and user corrections. Preserve units, source and drawing/setup scope. Use stable keys, read before replacement, and skip unchanged facts. Never save secrets, speculative geometry, transient revisions, failed operations, private reasoning or raw logs. Standing context affects later sessions: update it only for confirmed standing rules.

Delegate bounded work with real drawing/operation ids, units, constraints, target and expected report. Specialists receive your brief and their permitted tools; do not assume they see this conversation. Keep independent work moving while a job runs. Before accepting its report, inspect the relevant returned evidence and changed state.

After compaction, retain completed work and unresolved questions. Continue the native plan/goal from its recorded next action; refresh only identities/revisions needed by the next mutation. A completion report must distinguish persisted results, verified evidence, assumptions and blockers.
