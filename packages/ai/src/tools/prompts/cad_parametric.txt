Inspect, validate, create, update and test dimension-driven 3D parts in the editor's parametric feature history, generate standard engineering parts (recipe), look up fastener data (fastener) and check manufacturability (dfm). Never replace an existing part with unrelated geometry.

Parameters
- action: inspect | validate | create | update | test | recipe | dfm | fastener.
- elementId: existing parametric element id (inspect/update/test).
- history: parameters and ordered features (validate/create). Features form a discriminated union (type): sketch, extrude, revolve, hole, pattern, mirror, sweep, loft, shell, fillet. Referenced sketches and tools must precede their users. IDs are unique. Plane XY/YZ/ZX. Lengths mm; sketch angle constraints radians; revolve/pattern/taper angles degrees. Linear patterns need step [dx,dy,dz].
- name: part name (create); x, y, z: placement in mm; layer: optional existing or named layer.
- parameters: names mapped to finite numbers or expressions (update). Only existing names may change; derived parameters remain expressions unless explicitly changed.
- expectedRevision: revision from inspect; stale ones are refused without writing.
- cases: a JSON ARRAY of 1..12 objects, never a string. Each has name, parameters (existing names), optional expectedBodies, minVolumeMm3, maxVolumeMm3. Example: [{"name":"taller","parameters":{"height":25},"expectedBodies":1}]. Bounds/volume use local coordinates.

Exact history format
- history is a JSON OBJECT {"parameters": {...}, "features": [...]}, never a string of JSON, Markdown or code. Expressions are strings only inside parameters and dimension fields.
- Every feature has id and type. Every sketch entity has id and kind (NOT type): point {id,kind:"point",x,y}; line {id,kind:"line",p1,p2}; circle {id,kind:"circle",center,radius}; arc {id,kind:"arc",center,start,end}. p1/p2/center/start/end are point IDs, never coordinates. Coordinates and radii are finite numbers; drive them with constraints.
- Constraints use type, NOT kind: fixed {type:"fixed",point,x?,y?}; horizontal/vertical {type,line}; length {type:"length",line,value}; radius/diameter {type,circle,value}. Always include constraints, even []. A rectangle is four points and four lines in a closed loop, not kind:"rectangle".
- Every extrude/revolve needs operation (new|union|subtract|intersect) and sketch (an earlier sketch ID). A sketch alone makes no solid. Every hole/pattern also needs id and type.

Feature shapes beyond sketch/extrude/revolve/hole/pattern (sizes in mm, any dimension may be an expression)
- extrude.edge {style:"chamfer"|"fillet",size,ends?:"top"|"bottom"|"both",holes?} breaks the end-face edges (size < depth); extrude.corner {style,size} rounds/bevels sharp vertical profile corners (a fillet of the cutter radius makes inside corners machinable); extrude.taper = draft in degrees (walls lean, + narrows; 3 for a casting or mould; not with edge).
- hole.kind "counterbore" (headDiameter, headDepth) | "countersink" (headDiameter, angle default 90); size screw holes from the fastener action.
- mirror {feature,plane,offset?} reflects an earlier extrude/revolve/hole/sweep/loft/mirror tool through XY (Z), YZ (X) or ZX (Y).
- pattern kind "grid": count along step plus countB rows along stepB (both [dx,dy,dz]), at most 500 copies.
- sweep {profile,path,operation,bendRadius?}: profile = sketch with a closed loop (two nested circles = hollow tube); path = ANOTHER sketch with ONE open chain of lines/arcs, or one closed loop; the profile centre rides the path start; bendRadius rounds the path corners into pipe bends (omitted = mitred). {"id":"pipe","type":"sweep","profile":"section","path":"route","operation":"new","bendRadius":45}
- loft {sections:[sketch ids, 2..12],smooth?,operation}: the largest loop of each sketch (planes/offsets set the positions); sections are resampled to matching points. {"id":"duct","type":"loft","sections":["a","b"],"operation":"new"}
- shell {feature,thickness,open?:"none"|"top"|"bottom"|"both"}: hollow an earlier extrude, full 360 revolve or sweep with uniform walls (not a tapered extrude or a Boolean result); open = end faces left open (sweep: path start/end). Hollow revolved vessel: {"id":"vase","type":"shell","feature":"body","thickness":2,"open":"top"}
- fillet {radius,style?:"fillet"|"chamfer",edges?:{parallel?:"x"|"y"|"z",kind?:"convex"|"concave"|"both",minLength?,curved?,within?:{min:[x,y,z],max:[x,y,z]}}} blends edges between planar faces meeting at 25 degrees or more on the bodies so far (no edges = every convex edge); right-angled corners with three equal fillets get a spherical corner; rims of curved surfaces (round holes, cylinders) are skipped unless edges.curved:true (slow). A radius wider than the faces is refused: read the issues. {"id":"round","type":"fillet","radius":3,"edges":{"parallel":"z"}}

Actions recipe, dfm and fastener (nothing is written unless create is true)
- recipe: recipe = mounting_plate | flange | l_bracket | stepped_shaft | enclosure | pipe_bend | duct_transition; params = the design inputs, e.g. {"width":120,"fastener":"M8","counterbore":true}; create:true with name, x, y, z, layer also adds the part to the drawing. It returns summary, derived (hole sizes, positions), rules applied, the full history (fully constrained, key dimensions are parameters) and its rebuild report. pipe_bend takes bendRadius (default 1.5 x diameter, 0 = mitred). A broken rule (edge distance, hole spacing, keyway range, bend needing more run) returns ok:false with the rule named: change that input and retry. Prefer a recipe over hand-writing a standard part, then edit its parameters.
- dfm: send exactly one of elementId (an existing part) or history. process = mill (default) | turn | print; toolDiameter = smallest finishing cutter, mm (default 6); material = metal | cast | plastic; minWall mm; envelope {x,y,z} = machine travel or build volume. Returns ok (no errors), issues [{severity, code, feature, message, measured, required, fix}], metrics (bodies, volumeMm3, size, minWallMm). Codes: INTERNAL_CORNER, DEEP_POCKET, DEEP_HOLE, HOLE_EDGE_DISTANCE, HOLE_SPACING, THIN_WALL, EXCEEDS_ENVELOPE, SLENDER_TURNING, OVERHANG, SMALL_HOLE, NON_STANDARD_DRILL, UNDER_CONSTRAINED, LITERAL_DIMENSION, REBUILD.
- fastener: size = M2..M30 returns the thread (pitch, tap drill, clearance holes fine/medium/coarse, socket head, counterbore, countersink); fit picks the clearance series; no size lists every thread; shaftDiameter (mm) returns the DIN 6885 keyway (width, height, depths).

DFM workflow
After creating or changing a part to be machined, call dfm with the real cutter and material. Fix errors first by editing parameters or features (corner fillet at least the cutter radius, shallower pocket, more edge distance), then re-run dfm. State warnings to the user. Never call a part manufacturable without a dfm report with ok:true; run it before cam_create_operation.

Workflow and error recovery
1. For a new history, call action:"validate" first. Repair schema errors, unresolved expressions and rebuild errors before action:"create" with the same history and a name.
2. For existing parts, inspect the real elementId, then update parameters with the returned expectedRevision. On a stale revision, inspect again; do not guess it or replace the part.
3. Read the failing path. "history: expected object, received string" means send the object directly. "entities.N.kind" means check that entity against the four shapes above. It does not mean the tool is unsupported.
4. Correct the arguments and retry this tool. cad_add_elements validates parametric history with the SAME schema: switching tools does not fix it. Never repeat an unchanged rejected call. Read the result of a successful mutation before retrying to avoid duplicates.

Example: validate a dimension-driven cylinder (adapt the parameters)
```json
{"action":"validate","history":{"parameters":{"radius":10,"height":20},"features":[{"id":"profile","type":"sketch","plane":"XY","sketch":{"entities":[{"id":"origin","kind":"point","x":0,"y":0},{"id":"outline","kind":"circle","center":"origin","radius":10}],"constraints":[{"type":"fixed","point":"origin","x":0,"y":0},{"type":"radius","circle":"outline","value":"radius"}]}},{"id":"body","type":"extrude","sketch":"profile","depth":"height","operation":"new"}]}}
```
After ok:true, send action:"create", name and the same history. To update later: inspect the element id, then action:"update", elementId, expectedRevision and parameters such as {"height":25}.

Result
inspect returns history, revision, dependencies, rebuild metrics. validate returns ok, parameters, bodyCount, volumeMm3, bounds, issues, sketch solver statuses. create/update return editor-sync elements and ids; failed validation writes nothing. test returns per-case pass/fail, never changes the drawing and does not establish manufacturability. After updates use cad_check_design and cad_vision, then re-verify affected CAM operations.
