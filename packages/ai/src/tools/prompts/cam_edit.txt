Create CAM operations, generate G-code, set stock, verify toolpaths and store whole-part programs.
Call with action and its fields; use current revisions from CAM inspection/plan_check.

Actions and Parameters (mm, mm/min, rpm)
- create: type (mill: contour, pocket, drill, engrave, profile, threading, 3d_surface, probing, multiaxis; lathe: facing, turning, boring, grooving, parting, knurling), params, expectedRevision. params holds generator settings: toolType, toolDiameter, depth, stepdown, feedrate, rpm, material (aluminum|steel|wood|plastic|brass|titanium|composite|other), offset (inside|outside|center), workOffset, originType, machineType; printer extras infillDensity, supportType, shellCount.
- update: operationId, params, expectedRevision; changed settings invalidate NC.
- generate: operationId (required), maxLines (1-200, default 40); store full NC, return stats and preview.
- verify: operationId, tool {cuttingLength,shankDiameter,stickout,holderDiameter,holderLength}, fixtures [{id,bounds:{minX,maxX,minY,maxY,minZ,maxZ}}], targetSolids, stock (same bounds), resolution, tolerance, start {x,y,z}. Replay stored NC, never regenerate; persist evidence bound to programHash. Omitted geometry is unmodelled. Default start is X0 Y0 at stock top +10 mm.
- stock_set: stock {width,height,depth,radius,x,y,topZ,allowance,material?,elementId?}; change stock and invalidate programs.
- setup_save: name, setup (as cam setup_plan; plan it first), setupId + baseUpdatedAt to update a saved one (a stale baseUpdatedAt is refused, never overwritten). Saves the multi-operation setup in the project; stores no NC.
- setup_generate: setupId, expectedRevision?. Stores the programs of a saved setup, made from the drawing's elements; needs stock or the setup's stock block. Replays each work offset on its blank: programs[].release (blocked|preview|verified-program), evidence.
- export: kind program|stock|setup_sheet, operationId; program: extension? nc|tap|gcode|ngc|mpf; stock: format? stl|stl_ascii|obj|3mf (needs a current verify), unit?, name?; setup_sheet: HTML of a kernel program. Stores a file.
- probe: feature {elementId,ref?,hint?} or operation (cycle), operationId?, checks?, workOffset?, update?, tolerance?, frame?, dialect?, native?, machineConfig?, settings?, expectedRevision. Store a probe operation; never starts the spindle.
- probe_run: operationId, misplace?, machineConfig?, setupId?, calibrationError?, runId?. Simulate it, keep the report.
- probe_apply: machineConfig, reportId or entries, setupId?, mode add|set, baseUpdatedAt?. Refuses failed, stale or foreign reports.
- manufacture: material, machine, machineConfig, origin, setupOrientation, workOffset, setups (one program per setup; the job releases only if all do; result programIds by setup), carryStock, finishAllowance, scallop, deburr, tabs {count,width,height}, breadth {holeCycles,tilted,namedFeatures}, operations, tools, subprograms, nativeCycles, tcp, smoothing (mm contour tolerance), print (printers, as in cam manufacture), expectedRevision. Store whole-part NC and evidence; blocked releases refused. Preview: cam manufacture. machineConfig (from cam materials) wins over the preset id and supplies the post (its postDefinitionId); no postDefinition input here.
- turn: profile, stock, stepdown, allowance, feedMmRev, rpm, machine, machineConfig, expectedRevision (as cam turn). Store identical external-turning NC with lathe stock. Always preview; ideal point tool, unqualified workholding/controller. Re-run turn after changes, never legacy generate.

Result (JSON)
- ok; probe: operationId, programHash; probe_run: reportId, verdict; create/update: operationId; generate: programHash, lines/previewLines/omittedLines, preview; verify: status, programHash, issues, stats and modelling limits. manufacture/turn: operationId, release, identity.

Do not use it
- For reads or static analysis: use cam. A simulated pass proves only the supplied model.

After it
- On stale revision, inspect and plan_check again; do not substitute a guessed revision. Read cam review for the stored programHash. At most three refinements per drawing/stock revision, then report refinement_limit. Never regenerate a manufacture/turn program through legacy generate.
