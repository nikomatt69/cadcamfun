Write, change, enable, disable or remove a mod: a small extension module the host loads and runs, so a standing rule
survives without the user repeating it.

Authoring (the only shape the store accepts)
- Plain ESM, dependency-free: no `import`, no `require`. Everything reachable arrives on the hook's `$` argument.
- Export `register`: `export const register = (on, options) => { on("tool.call", { tool: "cad_edit" }, async ($, e, next) => { ...; return next(e) }) }`.
- `on(event, matcher?, hook)`; the matcher compares event fields (value, array of allowed values or a RegExp). A hook is
  `async ($, e, next)`, `e` is frozen: `return next(e)` to observe, `return next({ ...e, field })` to rewrite,
  `return { deny: "reason" }` to refuse a call, or `await next(e)` and return a changed result (wrap).
- The host skips a hook that throws or runs long; add the hook's own `.catch(...)` (on the object `on(...)` returns) when
  the rule must fail closed.

Events (e: fields; result)
- tool.call: tool, input, sessionID, agent, callID, plus the call's arguments top-level (`e.command`, `e.ids`, ...) ->
  a tool result `{ output, title?, isError? }`, `{ deny }` or `{ result }`. The place for "never allow this" and for
  annotations the user asked for.
- tool.check: tool, patterns, input, rule, sessionID -> `{ decision: "allow" | "ask" | "deny", reason? }`. The place for
  "always confirm before deleting" (`{ decision: "ask", reason }`).
- prompt.submit: text, context[], sessionID, agent -> a changed copy (`return next({ ...e, context: [...e.context, "…"] })`)
  adds text only the model reads; `{ drop }` is not for this application.
- session.start (reason), session.end, turn.start/turn.step/turn.complete (usage, answer, model), session.compact
  (`{ skip: reason }` leaves the conversation), skill.prompt (text), command.run, command.describe, agent.offer/spawn.
- ui.render (`{ tree }` drawn by clients that show mod panes), ui.press/input/select (`{ handled }`).

The `$` API (the essentials; every method is also an event name, e.g. `fs.read`)
- $ .ui: log, toast, notice, ask, copy, open/close panes, resolve(event) -> Box/Text/Button/... constructors.
- $ .tool.register({ name, description, args, execute }) -> a tool the model can call; dispose() to remove it.
- $ .command.register, $ .prompt.submit({ text }), $ .prompt.fill, $ .turn.abort, $ .session (id, cwd, messages,
  model, turns, repo, usage), $ .model.complete/classify (one completion on the user's own model), $ .agent.list,
  $ .mcp.call, $ .settings.read, $ .env.get/set, $ .fs (read/write/list/exists/stat/ancestors),
  $ .process.run/spawn, $ .http.fetch, $ .store (machine-wide key-value, 4 MiB), $ .state (in-memory, reload-surviving),
  $ .clock (now, sleep, after, every).

Actions
- save: write or replace one mod's source. Disabled unless `enable: true`; replacing keeps the current state.
- set_enabled: arm or stop one mod.
- remove: delete the module and its record. Not reversible; it exists only in action history.
- (This tool is destructive because of remove, so every call is confirmed by the person first.)

Parameters
- save: id (lower-case file name, e.g. `confirm_deletes`), name?, description (what it hooks and why), source, enable?.
- set_enabled: id, enabled. remove: id.

Result (JSON)
- A saved or toggled mod answers ok, id, enabled and events[] (what the live host reports); a removal answers ok, id,
  removed: true. A refused source answers ok:false with every problem the checker found.

Rules
- The mod applies to the whole application, not one project: write it for the standing rule the user stated.
- Enable, change or remove a mod only on the user's request (or with their yes after you offered). `mods` shows what
  exists; ask before replacing source you did not write.
- The user can see every mod's source in Extensions, switch it off and delete it; write source a person can follow.
- Changes reach the running host immediately; the next turn already runs under the new rule.
- Keep it small and single-purpose, and never store secrets in it.
