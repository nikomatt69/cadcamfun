Write, enable, disable or remove a mod: a standing rule that survives a restart.
A mod is a small extension module the host loads and runs; it acts on the whole application, not on one project.

Authoring (the only shape the store accepts)
- Plain ESM, dependency-free: no `import`, no `require`; everything reachable arrives on the hook's `$` argument.
- Export `register(on, options)`; register hooks with `on(event, matcher?, hook)`. The matcher compares event fields
  with a value, an array of allowed values or a RegExp.
- A hook is `async ($, e, next)` and `e` is frozen: `return next(e)` observes, `return next({ ...e, field })` rewrites,
  `return { deny: "reason" }` refuses, `await next(e)` and returning a changed result wraps. A hook that throws or runs
  long is skipped; add `.catch(...)` on the object `on(...)` returns when the rule must fail closed.
- Events (fields of `e`; what a hook may answer): tool.call (tool, input -> a result, `{ deny }` or `{ result }`; "never allow this"), tool.check (patterns, rule -> allow, ask or deny with a reason; "always confirm"), prompt.submit (text, context[] -> add text only the model reads), session.start/end, turn.start/step/complete, session.compact, skill.prompt, command.run/describe, spawn/offer, ui.render/press/input/select.
- The `$` API (each item is also an event name, e.g. `fs.read`): ui, tool.register (dispose() removes it), command.register, prompt.submit/fill, turn.abort, session, model.complete/classify, mcp.call, settings.read, env.get/set, fs, process.run/spawn, http.fetch, store (machine-wide, 4 MiB), state, clock.

Actions
- save: write or replace one mod's source. A new mod stays disabled unless `enable: true`; `enable: false` stops a
  running one; an absent flag keeps the current state. Replacing source you did not write: ask first.
- set_enabled: arm or stop one mod; an armed mod is consent to run it.
- remove: delete the module and its record. Not reversible.
- Every call is confirmed by the person first (remove is destructive).

Parameters
- save: id (lower-case file name, up to 40 characters, e.g. `confirm_deletes`), name? (up to 60), description (what it hooks and why, up to 200), source (up to 20000 characters), enable?.
- set_enabled: id, enabled. remove: id.

Result (JSON)
- save and set_enabled: ok, id, enabled, events[] (the events the live host reports for it now) and reloaded.
- remove: ok, id, removed: true. A refused source: ok:false with every problem the checker found.
- A mod that was armed but did not load (the host refused it) answers ok:false and is disabled again; read it back,
  fix the source, then enable it.
- If reload or inspection fails, the stored state is kept with a note; read it again before assuming its hooks are active.

Rules
- Enable, change or remove a mod only when the user asks or after they agree to your offer.
- The user reads every mod's source in Extensions and can switch it off or delete it; write readable source. Changes apply from the next turn.
- Keep it small and single-purpose; never store secrets in it.

Do not use it
- To read, list or review mods: `mods`.
- To change the drawing, the CAM program or project memory: `cad_edit`, `cam_edit`, `memory_edit`.
