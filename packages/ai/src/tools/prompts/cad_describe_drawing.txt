Read the drawing the user has open: what is in it, where, and under which ids.

Use it
- Before changing anything: ids are only known from here or from the result of an add call. Never invent an id.
- After building something, to check the count and the bounds against what you intended.
- When the user refers to "the part", "the hole" or "that wheel" and you need to know which element it is.

Do not use it
- To "look at" G-code or an operation: those have cam_list_operations and cam_generate_gcode.

Parameters
- none.

Result (JSON)
- total: number of elements.
- counts: elements per type, e.g. {"cube": 2, "cylinder": 4}.
- bounds: {min:{x,y,z}, max:{x,y,z}} in millimetres of everything drawn, or null for an empty drawing.
- elements: up to 200 of {id, type, name, layerId, x, y, z}.
- projectId, drawingId: where the elements are stored. An empty drawing is normal: the project and the drawing are created for you, so never ask the user to create them.

After it
- Empty drawing and the user asked for an object: build it with cad_add_elements.
- Elements present: refer to them by id in cad_modify_entities / cad_delete_entities.
