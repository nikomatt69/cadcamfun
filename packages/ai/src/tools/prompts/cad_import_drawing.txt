Read a 2D drawing (DXF or SVG text) or a prismatic STEP part and build it in 3D in the editor the user has open: every closed outline becomes a solid of the given thickness, circles and loops inside an outline become holes.

Use it
- The user attached or pasted a DXF, SVG or STEP file and wants the part: "make this plate", "extrude this profile 8 mm".
- A drawing the user dictates as DXF/SVG text.
- You read a dimensioned drawing or an image yourself: do not use this, build it with cad_add_elements from the numbers you read.

Do not use it
- For a flat sketch the user wants to stay 2D (cad_add_entities).
- To change geometry that is already in the editor (cad_modify_entities).

Parameters
- attachment: the name of a file the user attached to the chat (the message lists them under "Attached files"). Preferred: the file is read from the chat, you do not repeat it.
- content: instead of attachment, the file text itself, up to 2,000,000 characters. One of the two is required.
- format: "dxf", "svg" or "step". Default: from the attachment's extension, else from the text.
- depth: thickness in mm, > 0. A DXF or SVG has no height; ask the user if the request does not say. A STEP part brings its own height (its extent along Z), so depth may be left out.
- up: STEP only, "x", "y" or "z" (default z): the axis the part stands on, when it was modelled lying on another plane.
- scale: SVG only, millimetres per SVG unit (default 1; a 96 dpi SVG in px is 0.2646). DXF is read in its own $INSUNITS (mm, inch, cm, m) and always lands in millimetres.
- gap: how far two ends may be apart and still count as meeting, mm (default 0.01).
- tolerance: allowed deviation of curves from the true arc, mm (default the drawing's tolerance, else 0.01). Smaller is rounder.
- name, color, layer: optional.

What happens
- Lines, arcs and open polylines that meet end to end are chained into closed profiles; closed polylines, rectangles and ellipses are profiles already; circles stay true cylinders.
- An outline inside an outline is a hole (a boolean-subtract), a hole inside a hole is an island solid again. Solids stand on Z = 0 and grow along +Z.
- SVG y points down; it is flipped so the part is not mirrored.
- STEP (ISO 10303-21 text, mm/inch/m read from the file): the flat face looking down at the lowest level is the footprint, its outer loop and inner loops (lines, arcs, circles) are the outline and holes, the height is the part's extent along Z. This reads prismatic parts (plates, brackets, flanges, spacers). Steps, pockets with a floor, slopes and free-form surfaces are NOT read; warnings count them so you can tell the user what is missing. It does not replace a B-rep kernel.
- Anything it cannot close is NOT guessed: it is counted in stats.open and reported in warnings. Tell the user and offer a larger gap.
- Text, dimensions, hatches, splines and other non-outline entities are ignored and listed in warnings.

Result (JSON)
- Same as cad_add_elements (ok, ids, elements) plus stats {solids, holes, open} and warnings. ok: false with an error if no closed outline was found.

Uploaded STL (binary or ASCII), OBJ and PLY files are parsed by the desktop's installed Three.js loaders into attachments named `<source>.mesh.json`. Import these with attachment and format "mesh". Their source triangles and object transforms are retained. scale converts source units into mm (1 by default); consult the file/user units, never infer inches from its size. Mesh geometry is not a recovered parametric history and an open mesh is not a verified watertight solid. These attachments are limited to 40 objects and 30000 triangles, without silently simplifying the source. Other native binary formats require a decoder; do not claim they were read.

Desktop uploads of STEP/STP, IGES/IGS and BREP are decoded locally by OpenCascade and delivered as `.mesh.json` attachments, preserving triangulated surfaces, source face ranges and assembly paths in sourceMetadata. Import those with format mesh. STEP/IGES declarations are converted to mm by the decoder; default import scale 1 retains mm. BREP has no declared units: confirm source-unit scale. This route supports curved/free-form surfaces; the separate text STEP route above remains a prismatic fallback. No source parametric feature history is inferred. STEP/IGES requested triangulation deviation is 0.01 mm; BREP uses a declared 0.001 bounding-box ratio because units are unknown; numerical verification still uses reported CAM resolution. Unsupported native proprietary formats are reported as unread, never guessed or mocked.
