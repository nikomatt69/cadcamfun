# Security policy

## Reporting a vulnerability

Do not publish exploit details, credentials, pairing links, private drawings or
customer data in issues, pull requests, screenshots or logs.

Use this repository's GitHub **Security → Report a vulnerability** option if
available. This policy does not imply that private vulnerability reporting has
been enabled in repository settings. Otherwise contact Nicola Mattioli privately
through [@nikomatt69 on X](https://x.com/nikomatt69). If direct messages are
unavailable, request a private reporting channel without revealing the affected
system, exploit or sensitive details. Do not post those details as a reply on X.

Include the affected version or commit, platform, impact, prerequisites and a
minimal reproduction using synthetic data. Suggest a fix if you have one. Send
only information you are authorized to share. An encrypted channel can be agreed
before exchanging sensitive material; an X direct message is not a guarantee of
end-to-end encrypted delivery or confidentiality from the platform operator.

## Handling and disclosure

The maintainer assesses reports, may request more information, and coordinates
a fix and advisory where appropriate. Agree a disclosure timeline privately.
There is no guaranteed response time, security maintenance period or bounty
unless separately agreed. Reporter credit requires the reporter's consent.

Security fixes are prioritized for the latest released version and current
development branch as capacity permits. Older releases have no promised
backports. Upgrade before retesting a problem and retain a safe backup.

## Research boundaries

Test only installations, accounts, projects and machines you own or are explicitly
authorized to test. Use disposable data and simulated machining. Do not access
other people's data, disrupt services, run generated NC on real equipment during
security research, or test third-party providers without their permission.

This policy does not expand component licenses, authorize access to third-party
systems, or offer legal immunity on behalf of anyone. Mandatory legal rights
and third-party licenses remain unaffected. Ordinary bugs and usage questions
belong in [support](SUPPORT.md).
