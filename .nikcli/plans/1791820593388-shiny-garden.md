# CADCAMFUN: Native AI Architecture and Precision Roadmap

## Goal and scope

Analyse desktop AI, sidecar execution and the shared AI package; specify a professional, realistic native AI architecture for precise modelling and verified manufacturing. Fusion 360 / hyperMILL are product-direction references, not a current equivalence claim. The user selected all architecture areas and explicitly requires Effect v4 and nikcli.

This is a planning deliverable only. After approval, publish the contracts and step specifications described here; do not implement the entire roadmap automatically. Existing `specs/roadmap/README.md` remains the only implementation sequence. All RM rows are currently pending; RM-01 is first. Do not create a competing AI task board.

## Non-negotiable decisions

- Effect `4.0.0-rc.112` everywhere at application seams; `Context.Service`, explicit Layers, named `Effect.fn`, tagged errors, scope-owned resources and interruption. Read installed v4 docs before implementation.
- nikcli `@nikcli-ai/sdk-next@1.428.0` owns agent loops, sessions, native permissions/questions, delegation and compaction. Confine SDK coupling to `packages/ai/src/nikcli/`. No fork or replacement agent framework.
- AI SDK v7 remains stateless/one-shot only; it must not become another orchestration implementation or silently execute modelling mutations.
- Pure CAD/CAM implementations in `packages/core`; no Effect in geometry hot loops. SolidJS UI, Bun sidecar, Tauri supervision and Drizzle/SQLite stay.
- One application action catalogue; embedded nikcli calls it in-process. Typed HTTP/external nikcli is the second adapter, not an internal HTTP hop.
- No new dependency, kernel, paid provider call, production change or machine actuation as part of this planning/documentation work.
- No claim of perfect architecture, exact geometry, controller certification or commercial parity without reproducible acceptance evidence.

## Target architecture

```text
Solid desktop / paired mobile / standalone nikcli
    | typed intent, explicit document and revision, authorized actor
    v
Sidecar application modules (Effect v4, Layers, repositories)
    |                     ^ structured receipts / revisioned events
    v                     |
ActionCatalogue: one contract + one Effect execute per application action
    ^ embedded nikcli adapter     ^ typed HTTP adapter (RM-11)
    |                             |
nikcli host/session/specialists    external nikcli plugin
    |
Modelling and Manufacturing implementations
    v
Pure core: constraints/history/mesh -> setups/toolpaths/posts/NC verification
    |
DB-backed revisions, audit and durable task outcomes (sidecar/DB ownership)
```

The ActionCatalogue module earns depth: schema, documented effects, actor context, result contracts and transport parity acquire locality in one place. Its interface is the test surface. The embedded and external adapters supply leverage without duplicate dispatch. The modelling module earns depth by hiding deterministic construction and acceptance behind preview/commit; deleting it would push quality rules into prompts, handlers and UI callers. Runtime and workspace modules deepen existing implementations rather than add pass-through layers. Additional seams need two adapters or an explicit hypothetical-seam rationale.

## Core interfaces and invariants

### Action catalogue and execution

- Inventory every existing domain action with stable `tool.action` identity, schema, result schema, LLM documentation, effect classification, capabilities, exposure and transport mapping. Account/billing actions stay HTTP-only, not model-visible.
- Contracts shared with HTTP/UI live in dependency-safe `packages/api`; execution and model documentation live in `packages/ai`; implementations use sidecar repositories/core. `packages/api` must not import `packages/ai` or `db`. Preserve a single authoritative schema per input/result; bridge nikcli's zod requirement once and contract-test any unavoidable conversion.
- ActionContext carries authenticated actor, projectId, drawingId, client/host/parent session, turnId, actionCallId, expected revision and cancellation. Actor and owner are trusted application data, never model-supplied authority.
- Execute returns typed Effect with tagged failures and structured receipt. Promise conversion occurs only in the nikcli adapter, with interruption wired to its AbortSignal; no repeated `Effect.runPromise` inside business workflows.
- Separate authorization (resource rights), native nikcli permissions (tool capability/confirmation) and scheduling (write exclusion). These solve distinct problems, not competing permission systems.
- The host still authorizes tool IDs. A grouped tool with destructive actions must use the stricter native permission or a proven native escalation path; model-provided `confirm:true` is not human approval. This explicitly reconciles specs 26 and 27 before implementation.
- Effect classifications distinguish domain mutation, report persistence, UI-only effects, memory writes and external effects. Split read inspection from regeneration/persisted verification; treat workflow triggering as a write-capable operation.
- Actions that load context/inspect must not create drawings, mutate stock or provision default workspaces as a hidden side effect.

### Reliable document changes

- Sidecar owns persistent document revision, mutation receipt and derived-artifact invalidation. Receipt includes actor/owner IDs, document IDs, revision before/after, changes, invalidated artefacts and verification evidence references.
- Serialize writes per document and use optimistic revision checks. Validate all batched changes before one commit; check interruption before commit. No retry of unknown-outcome writes without idempotency/reconciliation.
- Operation key and parameter digest identify an invocation; repeat of a committed invocation returns its recorded receipt. This is idempotent commit behaviour, not exactly-once model execution.
- Desktop reducer applies each receipt once only to its matching document/revision. Different open document -> cache invalidation/notification, not mutation of the visible canvas. Missing revision/event gap -> authoritative snapshot reconciliation.
- Undo/redo for persistent changes crosses the same application execute seam; local viewport/selection commands remain UI-owned. Preview overlay is distinct from committed geometry.

### Precision modelling contract

- Modelling intent records dimensions, coordinate frames, units, datums, body/feature expectations, materials and independent requested tolerances. Missing manufacturing-critical dimensions become a native nikcli question, never an invented exact size.
- Preferred flow: inspect existing model -> resolve dimensions/references -> generate editable parametric feature history -> deterministic preview/rebuild -> measure -> bounded repair -> revision-checked commit -> re-read evidence.
- Preserve primitive insertion for simple tasks; prefer dimension-driven sketches/features for parts that need repeatable precise edits. No model-generated executable scripts or arbitrary code execution in the geometry kernel.
- Reuse `historySchema`, `rebuild`, `solveSketch`, `parametricReport`, `historyRevision` and tolerance helpers. Add typed acceptance to the existing modelling module, not a second modeller.
- QualityReport records requested/achieved tolerance, representation (mesh/parametric-mesh/exact only if supported), measurement provenance, constraint status/DOF/residual, dimensions/hole positions, bounds, expected body count, mesh degeneracy/manifold/winding checks where implemented, feature failures and uncertain/unsupported checks.
- Do not infer hole correctness from total volume or bounding box alone. Measure named design features and independent mesh sections/reference points against specified constraints.
- Separate dimensional tolerance, solver residual tolerance, meshing chord error, Boolean numeric epsilon, CAM chord/scallop tolerance, verification resolution and NC rounding. Do not pretend one setting proves all of them.
- Closed manufactured profiles require an accepted solver state; intentional remaining DOF must be declared. Error/skipped required feature prevents success. Tessellation caps, Float32 limits and unsupported checks produce visible limits, not fabricated precision.
- Repairs are bounded by attempts, computation and token budgets. No automatic save of failed preview; report specific residuals/features and request changed requirements when necessary.
- Existing degree-valued histories retain versioned legacy decoding. New canonical angles are radians; convert only in explicit legacy/UI/post adapters, including expression-valued angle fields. Test saved-document round trips before migration.

### Manufacturing evidence

- Revisioned setups bind part, stock, WCS, fixtures, cutter/holder, machine limits, post and units. Changes invalidate dependent operation/program/verification identities.
- The model selects verified operations/parameters through typed actions; deterministic generators/posts own toolpath/G-code. LLM G-code suggestions are untrusted candidates until parsed, checked and replayed.
- Verify the actual emitted/stored NC artifact and hash, not silently regenerate a different program and label the old one verified. A separate generate-and-verify write workflow may exist.
- Reports state what was modelled: target, fixtures, holder, stock resolution, machine/kinematic coverage and unknowns. Passing simulation is not machine certification. No autonomous physical machine command.

### Context, lifecycle and telemetry

- Workspace snapshot is typed, versioned, authorized and revisioned. Desktop contributes selection/view/unsaved intent; sidecar supplies authoritative model/setup/artifact evidence. One budgeted renderer, no duplicate prompt builders.
- User-global preferences are distinct from project notes. No `kv.list('ai.memory.')` across projects/actors in prompt assembly. Memory/instructions/attachments have provenance and trust labels; reference text cannot authorize writes.
- `includeContext=false` must have a specified server meaning and be tested end-to-end; authorization/identity are never disabled by it.
- Owner is actor + project + parent session. Capture immutable context at enqueue; retries/wakes cannot inherit the latest turn's actor. Session control/removal/permission/question replies validate owner.
- Preserve scoped host caching, bounded scheduler, cancel/join/retired-parent semantics and disconnect != abort. Extend, do not reimplement nikcli lifecycle.
- Durable job outcomes use SQLite leases/attempts and commit-before-delivery. Recover read jobs; uncertain write outcomes reconcile revision/receipt and require review instead of blind replay.
- Events carry eventId/sequence, owner/session/turn/task/attempt/document revision. Bounded subscribers return an explicit resync condition; snapshots bridge retention gaps. Keep polling as fallback until reconnect/replay tests pass.
- Usage/cost/latency, recovery, quality failures and artifact revision telemetry are redacted and correlated. Pricing unknown -> unavailable, not zero. Do not log secrets, full parts/prompts or provider bodies by default.
