# Desktop UI Design Polish

## Objective

Polish every built CADCAMFUN desktop UI component in `apps/desktop/src` with Apple design and Emil Kowalski design-engineering principles. Work synchronously (no background tasks), preserve all pre-existing worktree changes, and prioritize the existing CAD/CAM application visual language rather than imposing a generic redesign.

## Scope and approach

1. Inventory built screens, shared primitives, CAD/CAM controls, assistant/settings, shell/navigation and responsive states. Exclude generated artifacts and domain/backend packages; do not mistake legacy route stubs for implemented UI components.
2. Establish consistent component-level foundations: platform typography, intentional tokens, high-contrast workspaces, clear interaction hierarchy, immediate pointer-down feedback, fine-pointer-only hover, visible keyboard focus, reduced-motion/transparency/contrast support, and responsive/safe-area layouts.
3. Refine components by user-facing surface, keeping layout and behavior recognizable: app shell/navigation; projects/library/settings; CAD editor and browser; CAM generator, verification and G-code; AI assistant and settings; shared buttons/forms/modals/sheets/toasts/alerts/status.
4. For each component, retain existing contracts and functionality; improve interaction semantics, disabled/loading/empty/error states, hit areas, labels, keyboard access, dark mode, and motion only where it communicates feedback or spatial continuity. Do not animate high-frequency keyboard actions, avoid decorative motion without a clear purpose, use interruptible transitions for rapidly changed UI, and only use springs for gesture-driven movement that benefits from velocity handoff. Keep UI animation under 300ms where appropriate; honor reduced motion/transparency/contrast.
5. Preserve the current dirty worktree: inspect each target's existing diff before changing it, edit only UI-owned files, and never discard or rewrite unrelated user changes.

## Verification

- Run `bun run --filter @cadcamfun/desktop typecheck` after each coherent batch.
- Run focused relevant tests for changed UI behavior, then `bun test apps/desktop/test` when feasible.
- Run `bun run --filter @cadcamfun/desktop build`; if it stalls/timeouts, diagnose the bottleneck and report the exact outcome rather than treating it as passed.
- Run `git diff --check`; inspect final changed-file list/diff to ensure no unrelated work was altered.
- Where browser execution is available, inspect the built desktop UI at desktop and narrow viewport sizes and check interaction/focus/reduced-motion states.
