The CADCAM Agent

A bespoke CAD/CAM colleague built as an nikcli-style coding/terminal agent, retargeted at building geometry and machining programs on the project the user is editing. It uses CADCAMFUN elements, edits them, saves them, looks up materials / tools / machines / toolpaths in the library, sits inside a git-style history, runs Actions-style workflows on every commit, and reaches the user through the same chat on the iOS companion.

"What nikcli does for the code editor, the cadcam agent does for the CAD/CAM editor."

Codebases nikcli @ /Volumes/SSD/Development/nikcli-main · cadcamfun @ /Volumes/SSD/Development/cad-cam-app-main-prod-main-prod-v2-auth-proveder-2

1. Architecture

The cadcamfun AI layer (packages/ai) embeds nikcli's sdk-next in-process. The host runs with an isolated config (no ~/.config/nikcli read), a deny-by-default cadcam agent whose only allowed tools are the ones this package registers, no shell / file tools, a four-specialist roster, and ten skills that are loaded on demand.

User ──► Desktop (Solid + Three viewport) ──► Sidecar (Bun + Effect + HttpApi) │ ├─ AiService (packages/ai/src/service.ts) │ ├─ AiCredentials (credentials.ts) │ ├─ AiCache (cache.ts) │ ├─ DirectModel (direct-model.ts) │ └─ AiHost (nikcli/runtime.ts) │ ├─ cadcam agent (deny-by-default) │ ├─ 4 specialists: researcher / editor / modeler / machinist │ ├─ 22 built-in tools (+ N extensions via plugin SDK) │ └─ 10 skills + N user skills │ └─ Sidecar services ├─ ProjectRepo (cad/cam editing handlers) ├─ ProjectVcs (vcs tools on top of packages/vcs) ├─ WorkflowRunner (apps/sidecar/src/services/workflow-runner.ts) └─ CompanionGateway (apps/sidecar/src/services/companion-gateway.ts)

The principle

The agent's effective view of the project is the workspace context renderer plus the system prompt plus the conversation history nikcli holds. Nothing else reaches the model. Tool calls return to the editor immediately; tool calls that touch the repository land on a reviewable ai/* branch; a person always reviews and merges. Credentials and shell are out of reach by construction.

4. Parametric drawings & composed CAM programs

4.1 Parametric — parametric element

The agent builds a parametric part when the user wants named, changeable dimensions ("a plate with M holes on a ring of Ø D, where M, D and thickness are named parameters"), and edits it later without rebuilding it from scratch.

{
  history: {
    parameters: { width: 60, depth: 40, thick: 8, hole: 5, count: 4, ringD: 40, finish_mm: 0.3 },
    features: [
      { id: "plate", type: "sketch", plane: "XY", sketch: { entities: [...], constraints: [...] } },
      { id: "body",  type: "extrude", sketch: "plate", depth: "thick", operation: "new", direction: "up" },
      { id: "h1",    type: "hole", plane: "XY", offset: "thick", at: ["width / 2", "depth / 2"], diameter: "hole", depth: "thick" },
      { id: "ring",  type: "pattern", feature: "h1", kind: "circular", centre: ["width / 2", "depth / 2"], count: "count", step: { angle: 360 } }
    ]
  }
}

Resize = cad_modify_entities { parameters: { width: 70 } } (features stay). Add a feature = cad_add_elements appended to the same history. Refactor features = overwrite the whole history (destructive, with tool-level confirmation in a future major).

4.3 Sequencing rules

  1. Probe first, machine after. probing writes the work offset; milling uses the same workOffset.
  2. Face / clear the top, before rough. Reference plane comes first.
  3. Rough, then finish. Leave 0.1–0.3 mm in finish_mm. Climb milling, stepover 5–15 % D.
  4. Drill before tap or thread-mill. Peck 3 × D; pilots for Ø > 12 mm.
  5. Engrave / chamfer last. Touch a finished surface.
  6. Indexing after the bulk is removed. Orient is a move between operations.

4.4 Verifying per operation

The strict pattern the machinist specialist runs:

1. cad_describe_drawing       -- what is there
2. lib_lookup_material/tool   -- never invent
3. cam_suggest_parameters     -- depth/stepdown/cutting stats + warnings
4. cam_create_operation       -- one at a time
5. cam_generate_gcode         -- regenerates from data.request
6. cam_analyze_gcode          -- static checks (no LLM)
7. cam_verify_toolpath        -- simulate on stock
8. cam_update_operation       -- by cause, not symptom
9. repeat 5–8 until clean (max 3 rounds; report what blocks)

7. Context awareness

The agent's effective context = the workspace renderer (packages/ai/src/workspace-context.ts) + the system prompt (packages/ai/src/prompts/system.ts) + the conversation history.

7.1 Sections in priority order

  1. Document + units ("Workspace: CAD editor, drawing "...". Units: tool calls in mm; the user reads mm. Drawing tolerance X mm. View: 3D.")
  2. Selection (model counts, breakdown, selected ids)
  3. Layers (visibility, locks, active)
  4. Stock (W × H × D mm)
  5. Machining (machine / controller / post / material / operation / tool / offset)
  6. Toolpaths (first 8 with move counts)
  7. Verification (state: not-run | stale | ok | errors; first 4 issues)
  8. G-code size + attached files
  9. Elements (starred selection; remainder says "N not shown — call cad_describe_drawing")
  10. G-code preview (first 12 lines)

7.2 Honesty contract

Every numeric value in tool calls is in mm or rad. rotation in degrees; arc / revolution in radians. No unit symbols inside numbers (50, not 50mm). The renderer never invents a field; the agent reports what a tool result confirmed; the agent says "no errors found in what was modelled", never "safe".
