# Professional CAD/CAM Architecture

Status: foundation hardening and a first verification module implemented; commercial parity not established.

The owner-requested [native CAM kernel architecture](29-native-cam-kernel.md) expands the manufacturing design with stock-aware generation, machine kinematics, continuous assembly checking and independent final-NC verification. It is a design contract, not an implementation or qualification claim; existing acceptance gates and implementation sequence still apply. Its current-source inventory supersedes historical CAM limitation summaries below where subsequent code has already landed.

## Evidence and scope

Official sources inspected on 2026-10-07:

- https://www.openmind-tech.com/en/cam/ describes hyperMILL drilling, 2.5D/3D/5-axis milling, turning, machine-specific postprocessors and simulation driven by generated NC code rather than only internal CAM data.
- https://www.mastercam.com/solutions/ describes 3-axis through simultaneous 5-axis machining, turning, mill-turn, wire EDM, Dynamic Motion toolpaths and GPU-accelerated simulation.
- Autodesk product-page requests returned HTTP 403 in the local fetch tool. Fusion claims must be backed by accessible official documentation before becoming acceptance requirements.

These are capability references, not comparative performance benchmarks or machine certifications. The existing WP1 scope explicitly excludes Boolean CSG and sketch constraints; WP2 excludes material removal, collision checking and 4/5-axis. Those exclusions conflict with broad professional parity and must be deliberately superseded in future work packages.

## Existing Modules and deepening

| Module | Existing Interface / Seam | Implemented improvement | Remaining limitation |
| --- | --- | --- | --- |
| Solid geometry | `meshOf`, `solidBounds` | Handedness-preserving axis mapping, actual torus surfaces, concave cap triangulation, ordered negative extrusion bounds, partial sweep extrema, tolerance-driven bounded subdivision | Triangle meshes are not exact B-rep solids. Exact topology, exact Booleans and STEP read/write live in the separate native kernel `cad/brep/` (spec 03 §7c); constraints and feature history in `sketch.ts` / `history.ts` (spec 03 §7b) |
| Drawing migration | `migrateDrawing`, `droppedEntities` | Strict current-document decode preserves entities and metadata; legacy reconstruction remains distinct | Interchange coverage and legacy formats need a larger fixture corpus |
| Drilling cycles | `expandCycle`, post emission | Shared cycle safety checks, numeric progress limits, pre-positioning lift, repeated-hole execution and dwell reset | R-plane clearance is not a fixture/tool-envelope proof |
| NC arcs | Post emission | Reject invalid geometry and unknown starts; precision-collapsed short arcs cannot accidentally become full circles | Controller-specific rounded geometry and full option validation remain |

Keep geometry and toolpath Implementation pure and I/O-free. The existing public Interface is the test surface; strengthen invariants there rather than duplicate checks in UI callers. Shared axis mapping and cycle checks improve Locality and Leverage without replacing the Bun/Effect/Solid/Tauri architecture.

## Engineering design layer (feature history, design rules, recipes)

Implemented on top of the mesh feature history (`packages/core/src/cad`), reachable by the assistant (`cad_parametric` actions `recipe`, `dfm`, `fastener`), the sidecar (same `historySchema`, no new routes) and the desktop Parametric panel (edge / corner / hole-kind controls, editors for sweep / loft / shell / fillet / grid, add-feature shortcuts, a Manufacturability section, a Recipes picker; the panel was driven in a DOM with a live store, not yet in the Tauri window):

| Capability | Where | Honest limit |
| --- | --- | --- |
| Mesh kernel under every Boolean: list-form BSP with bounding-box culling and a convex-plane classifier (a convex operand is its distinct face planes, no quadratic chain), then `cleanPolygonSoup` (weld, T-junction repair, coplanar fragments merged into faces and re-triangulated, short-edge collapse, flat-triangle and sub-micron-crack repair); `meshTopology` (closed, shells, genus, open / non-manifold / flipped edges) reported per body to the assistant (`parametric_validate` `solids`); `creasedNormals` (30 degree crease) in both viewports; earcut-style triangulation with holes | `csg.ts`, `mesh-clean.ts`, `mesh-topology.ts`, `mesh-normals.ts`, `triangulate.ts` | Still faceted meshes, not B-rep. Measured: plate minus 40 holes one by one about 1.4 s (never finished before), sphere of 9 800 triangles minus a box 0.1 s (16 s before), every recipe and every catalogue solid a closed solid with the expected genus. Nearly tangent operands can still leave non-manifold contact; the edge-blend rolling-ball corner is offset (cylinders +0.4 %, ball +2 %) so it does not. |
| Edge chamfer / fillet of the end-face edges of an extrusion, and rounding / bevelling of sharp profile corners (`extrude.edge`, `extrude.corner`) | `profile-shape.ts`, `history.ts` | Exact on prismatic extrusions of a sketch (the profile is lofted through inset copies). Not a general B-rep fillet: edges of revolved bodies, Boolean results or arbitrary faces cannot be filleted. A radius larger than the narrowest feature is refused with the reason. |
| Draft (`extrude.taper`, degrees, + narrows towards the far end; holes in the profile lean with it) | `profile-shape.ts`, `history.ts` | Prismatic extrusions only (the profile is lofted through inset copies); not combinable with `edge`; a drafted extrusion cannot be shelled. Draft on faces of other bodies is not available. |
| Counterbore and countersink holes, `mirror` feature | `history.ts` | The mirror reflects the tool of an earlier extrude / revolve / hole / mirror; there is no mirror of a whole body or of selected faces. |
| ISO metric fastener data (ISO 262 / 273 / 4762 / 7046, DIN 974), DIN 6885 keyways, ISO 286 tolerance grades | `fasteners.ts` | Tables, not a standards library: M2 to M30 coarse thread, form A keys for 6 to 75 mm shafts. |
| Design for manufacture (`analyzeManufacturability`): internal corner radius against the cutter, pocket depth ratio, drilled-hole ratio, hole edge distance and spacing, thin walls (ray sampling), machine envelope, turned slenderness, print overhang and small holes, under-constrained sketches, literal dimensions | `dfm.ts` | Rules of thumb with overridable limits, not a simulation: it does not model fixturing, tool holders, chatter, thermal effects or the actual machine, and thin-wall sampling can miss a localised thin spot between samples. A report with no errors does not certify a part. |
| Recipes (`mounting_plate`, `flange`, `l_bracket`, `stepped_shaft`, `enclosure`, `pipe_bend`, `duct_transition`) | `recipes.ts` | Seven generators that apply the rules above and return a fully constrained history; they enforce edge distance, spacing and keyway ranges and refuse impossible inputs. `pipe_bend` is a long-radius elbow by default (`bendRadius` 1.5 x the outside diameter, 0 = mitred) and refuses a bend that needs more straight run than there is. Ribs, lids, sheet-metal bends and other families are not generated yet. |
| `sweep` (profile along an open or closed path sketch, parallel-transport frames, optional `bendRadius` that rounds the path corners into tangent pipe bends, otherwise mitre stretch at path corners, nested loops = hollow), `loft` (resampled sections matched by start point, optional Catmull-Rom smoothing) | `sweep-loft.ts`, `history.ts` | Mesh solids with real caps. The path sketch holds ONE open chain of lines / arcs or one closed loop; a closed non-planar path can twist at the seam; `bendRadius` applies to open paths and is refused when a straight run is shorter than the bend's tangent length (the volume follows Pappus: area x centre-line length). A loft uses the largest loop of each section and resamples it, so sharp corners of very different sections are softened; no guide rails or tangency conditions. |
| `shell` (hollow an extrusion, a full 360 degree revolution or a sweep; open none / top / bottom / both) | `history.ts` | Exact on those three sources: an extrusion inset profile (holes grow), a revolution profile mirrored across its axis, moved inwards and cut back to the half-plane, a sweep of the inset profile (a closed hollow stops one wall short of each path end; open = path start / end). Not available on a Boolean result, a loft, a partial revolution or a drafted extrusion, and no per-face thickness. |
| `fillet` / chamfer of selected edges of any body (`edges`: parallel to an axis, inside a box, convex / concave, minimum length) | `edge-blend.ts`, `history.ts` | Edges are recovered from planar faces that meet at 25 degrees or more, so only straight edges between planes; an edge against a curved face is not a straight line and is not blended. Planar facets that meet at a shallow angle are grouped as one curved surface (a tessellated hole, cylinder or an earlier fillet): their rim edges are flagged `curved` and left out of a default selection (`edges.curved: true` takes them, one Boolean per facet, which is slow). A radius wider than the faces is refused with the edge named. Where three EQUAL fillets meet at a right-angled convex vertex the corner is a rolling-ball sphere octant (the tricylinder left by the three edge tools is cut back to the ball); any other vertex (unequal radii, chamfers, non-orthogonal faces, concave vertices) is still a mitred overlap of the tools, not a blend patch. A rim of a round hole is therefore not filleted by this feature (use `extrude.edge` with `holes: true` on an extrusion). |
| `plane` work planes (offset, angle about u or v, three points, on a planar face) used by sketch / hole / text, with a sketch on a face that follows the face | `history.ts`, `face-edit.ts` | A face plane needs a watertight mesh and picks the face by a point; if the face disappears the plane is reported and everything on it is skipped. Split and mirror still take only XY / YZ / ZX. The DFM hole checks skip holes on work planes. |
| `draft` (one planar face of any body tilted about its neutral-plane hinge; a curved face drafted one way from a neutral plane at its base or top, `smooth-face.ts`) and Press Pull of curved faces (offset along the area-weighted vertex normals of the tangent-continuous face: a cylinder changes radius by exactly the distance at its vertices; an offset that folds the face is refused) and `mate` (rigid face-to-face joint: normals opposed, centres together, gap, spin) | `history.ts`, `face-edit.ts` | Planar faces only; one feature per face, and a drafted face cannot be coaxial with the pull direction. The joint is one rigid motion of the whole body posed by `offset`, `spin` (revolute) and `slide` (slider / planar), checked against `limits`, with an interference warning (one Boolean per mate); there is no motion study, no cam or gear joint and no solving of several joints together. |
| `rib`, `sheet`, `thread`, `text`, `pushpull` (Fusion's Rib, sheet-metal base flange, modelled Thread, Text, Press Pull) and the `model()` scripting builder | `sheet-metal.ts`, `thread.ts`, `text-solid.ts`, `face-edit.ts`, `helix.ts`, `script.ts`, `history.ts` | Rib: open chains thickened by offset curves (butt ends). Sheet: one open chain, the INSIDE radius is honoured on both sides of the line, volume and developed length verified against the closed forms; `hems` fold a flange back (two 90 degree bends, gap at least twice the inside radius) and `flatPatternDrawing` / `flatPatternDxf` give the blank (CUT) with a bend line per bend (BEND); no reliefs, no corner closures. Thread: ISO 68-1 basic profile swept along a helix with the profile kept radial (`sweepSolid`'s `axis`), 0.7 % under the analytic ridge volume at 32+ chords per turn; a thread is a tool (rod / tapped-hole cutter), or with `cut` the groove taken off an existing shaft (a wider shaft is turned to the major diameter over the thread length); along Z, X or Y only. Text: single-stroke capitals/digits/punctuation, square stroke ends. Press Pull: planar faces only, selected by a point (T-junction tolerant, holes kept); it needs a watertight mesh. Scripting: the builder writes a `History`; running source text needs `unsafe-eval`. |
| `pattern` kind `grid` (rows x columns) | `history.ts`, `dfm.ts` | Copies the tool of an earlier extrude / revolve / hole / sweep / loft / mirror; at most 500 copies. Copies whose bounding boxes do not overlap are applied in ONE Boolean (a 3 x 2 hole grid rebuilds in milliseconds); overlapping copies fall back to one Boolean each. This applies to linear and circular patterns too. |

Still missing for the kernel gate in step 1 above: an exact B-rep (fillets against curved faces, variable radius, vertex blends other than the equal right-angled case, shell of a Boolean result or any body, sheet-metal reliefs,  draft of faces that are not an extrusion's walls, loft guide rails and tangency), exact STEP export, and assemblies with mates.

## Technical drawings from the 3D model (`packages/core/src/drawing/`)

Integration contract (2026-10-13): WP1 owns drawing projection/layout; WP8 exposes read-only `cad.drawing` alongside the parametric actions; WP4 resolves the active accessible part through its existing parametric handler; WP6 owns a CAD ribbon entry and drawing preview/export panel. Matching tests are in those workspaces. No document persistence or new route is required. `cad.drawing` accepts exactly one `elementId` or validated `history`, plus bounded sheet options, and returns SVG, dimensions, callouts, scale and warnings without creating geometry. The desktop uses the same core generator for a selected parametric part in its local model coordinates. SVG is vector; PDF export is a single landscape page at its declared millimetre size, rasterised at 300 dpi with the browser's fonts to preserve Unicode drawing symbols. Both exports retain all reported layout warnings. These adapters must reject invalid options and failed rebuilds.

Drawing limits: feature dimensions cover principal-plane holes and their supported patterns; arbitrary work-plane holes, transformed feature annotations, complete GD&T, assembly drawings/BOM, associative drawing editing and guaranteed collision-free layout remain unsupported. Mesh projections are approximate, hidden-line visibility is sampled, and the PDF contains an image rather than searchable/vector entities. Exact B-rep and STEP exchange exist in the native kernel (`cad/brep/`, spec 03 §7c); STEP re-import equality within declared tolerance on the reference corpus is the open part of gate 1 below. Threads on existing cylinders, curved-face push/pull and draft, and non-rigid parametric joints remain separate kernel work; a sheet export does not implement them.

Target (user, 2026-10-13): a Fusion-style production sheet generated from the model, as in `specs/assets/reference-drawing-liquid-mixer.png`
("Liquid mixer v2": front / top / side / isometric views, detail A (2:1), section B-B with hatching, dimensions with tolerances, hole
callouts, flatness frame, title block, notes, zone grid). Written before the code; the acceptance test below is what "done" means.

**Pipeline** (each stage is a pure function, tested alone):

1. `project.ts`: a `History` body (or any closed mesh) to 2D edges for a named view (`front`, `top`, `right`, `left`, `back`, `bottom`,
   `iso`). Edges are the creased edges of the mesh (dihedral angle over 30 degrees), the boundary edges, and the silhouette edges
   (a front-facing and a back-facing triangle meet). Hidden-line removal: each edge is sampled along its length, a sample is hidden
   when the segment from it to the viewer meets a triangle (uniform 2D grid over the projected triangles), runs are merged and their
   ends bisected. Result: `visible` and `hidden` polylines in view coordinates (mm), plus the view's bounds. The mesh-edge source sits
   behind one function (`edgesOf(mesh)`) so exact B-rep edges (the `exact-brep-kernel` branch) can replace it without touching the
   stages after it.
2. `section.ts`: a body cut by a plane: the section loops (plane-triangle intersection chained into closed loops), the part of the body
   behind the plane projected as a view, and hatch lines (45 degrees, even-odd fill) that lie only inside the loops. `detail.ts`: a
   circular region of a view enlarged by a factor, edges clipped to the circle.
3. `dimensions.ts`: dimensions come from the **history features**, not from the mesh: holes (simple, counterbore, countersink), threads
   (tapped hole = `M4-6H`, `G1/2"`), fillets / corner radii, extrusions (overall sizes), with equal holes grouped as `N x`. Tolerances
   are written as ISO 286 deviations (`tolerance.ts`, `fasteners.ts` tables). A dimension is data (`kind`, anchor points, text,
   tolerance), laid out by `layout` rules (nearest to the view first, fixed spacing), never placed by hand.
4. `sheet.ts`: sheet size (A4 / A3 / A2 landscape), frame with zone grid, title block (material, colour, finish, standard, projection
   symbol, scale, sheet, revision), general notes, view labels and scales, and the first / third angle projection symbol; the arrangement
   follows the projection angle. Output is a core `Drawing` document, serialised by `svg.ts` (new) and `writeDxf` (existing).

**Acceptance (the gate).** `drawing/liquid-mixer.test.ts` rebuilds the part in a `History` (120 x 70 x 45 block with R10 corners,
figure-eight boss, 2 x Ø8 THRU ALL counterbored Ø13.5 depth 8.5, 2 x Ø8.1 +-0.1 countersunk 10 x 90 degrees, 6 x Ø3.3 depth 12, M4-6H
depth 8, G1/2"-6H depth 18) and generates the sheet: the dimension values and callout strings are compared with the reference, the
views are counted, the section hatch must lie only inside the cut region, and the SVG is written to `data/drawings/liquid-mixer.svg`.

**Not covered, said honestly:** GD&T beyond a flatness frame, balloons and bill of materials, surface-finish symbols other than the note,
exact (analytic) edges and silhouettes of curved faces (a faceted cylinder's outline is drawn from its facets), automatic collision-free
dimension placement for crowded parts (spacing is rule-based; overlapping text is detected and reported, not solved), assembly drawings,
PDF output (follow-up), a drawing editor in the desktop app beyond a preview panel. Parity with a commercial drawing module is not claimed.

## Integration order and acceptance gates

1. **Geometry kernel Module** (a mesh CSG, a constraint sketch solver, a parametric history and a native exact B-rep kernel exist, spec 03 §7b–§7c: `cad/brep/` reads and writes STEP, and `history-brep.ts` replays the exact feature set it documents — extrude, revolve, line/arc sweep, holes, fillets and chamfers of straight and coaxial edges, shells of extrusions, revolutions and sweeps, exact Booleans — while any other body keeps its mesh and says why; the gate below has **no recorded evidence** yet: no reference-part corpus with measured dimensions and STEP re-import equality): mesh primitives stay the rendering Adapter and exact topology enters only through the `cad/brep/` Seam. A third-party kernel is not adopted without a separate ADR (license, Bun/Tauri deployment, deterministic STEP round trips). Gate: Boolean/fillet/shell reference parts, valid manifold topology, measured dimensions and STEP re-import equality within declared tolerance. A mesh must never masquerade as exact geometry.
2. **Manufacturing setup Module:** immutable work coordinate frame, revisioned part/stock/fixture/tool-holder geometry and machine profile. Gate: all transformations and units have round-trip tests; changes invalidate derived toolpaths and verification evidence.
3. **Verification Module** (first version implemented, spec 04 §10: height-field stock removal, rapid / shank / holder / fixture / below-stock findings, gouge against target solids, AI tool and desktop tab; 3-axis only, no swept-volume collision against the finished part or machine kinematics): consume both Toolpath IR and emitted NC through their existing Seams. Start with the real interpreter Adapter, then add stock-removal and swept cutter/holder collision tests. Gate: detect deliberate gouges, remaining stock and fixture collisions, including arcs, helices and cycles. Path animation alone is not verification.
4. **Strategy Module** (surface roughing / parallel / waterline **rest roughing from a previous tool** and **adaptive (engagement-bounded) clearing** implemented, spec 04 §12; rest finishing / pencil and thread milling implemented; still missing: stock-model rest carried between operations, 4/5-axis): extend current Profile/Pocket/Drill/Face/Engrave only after setup and stock evidence exist; add surface finishing, rest machining and engagement-bounded roughing. Gate: independent geometric no-gouge tests, declared chord/scallop tolerances and bounded computation on benchmark parts.
5. **Machine/post Module** (indexed 3+2 on a trunnion table implemented, spec 04 §13: rotary angles from the work frame, program in machine coordinates; still missing: kinematic collision checking, head-tilt machines, controller tilted-plane cycles, simultaneous 5-axis): preserve existing generic/Fanuc/GRBL Adapters and deterministic goldens. Add explicit machine kinematics, axis travel, safe tool changes, holder clearance and controller limits before simultaneous multi-axis strategies. Gate: emitted-NC replay agrees with intended motion, then controller simulation and supervised machine dry runs on identified machines.
6. **Desktop integration:** expose verified capability and structured failures through documented API contracts before changing sidecar/UI-owned directories. Gate: desktop project-to-export workflow tests, stale-result invalidation, cancellation and large-part responsiveness.

No new kernel dependency, pretend simulator, empty strategy or unvalidated postprocessor is introduced by this hardening. Future machine validation needs actual machine/controller profiles, fixture/tool-holder dimensions and representative reference parts. Do not describe the present application as equivalent to Fusion, hyperMILL or Mastercam until these gates have reproducible evidence.
