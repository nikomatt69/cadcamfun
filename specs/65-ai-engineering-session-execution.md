Status: implementation in progress (owner-requested, 2026-10-28).

The owner explicitly requested implementation of all six findings from the nikcli session comparison, with four agents working in parallel, production code first and focused verification without adding regression-test files. This is a concrete feature/fix request under `roadmap/00-how-to-follow.md` §1; it does not mark the unrelated RM-01/RM-03/RM-06/RM-07/RM-10/RM-11 gates complete or replace their sequence. Receipt-dependent editing recovery remains disabled until its receipt guarantees are available.

## Contracts and ownership

1. **Durable tasks (WP8/WP4).** Deepen `nikcli/background-tasks.ts`, `background-tools-runner.ts`, `background-tools.ts`, `background-layer.ts` and `services/ai-task-journal.ts`. Enqueue, report, terminal outcome and delivery acknowledgement are ordered durable transitions. A storage failure must not acknowledge a successful terminal result. Preserve child evidence on failed report storage. Parent delivery retries use a stable native message identity; cancellation remains terminal. Persist a frozen trusted target and child identity. Lease acquisition/renewal uses atomic storage operations; recovery must not replay editing work with uncertain effects.
2. **Command receipts (WP0/WP3/WP4/WP8).** Deepen the existing action execution seam and database implementation. Propagate trusted host message/call identities, bind command identity and input digest to actor/project/drawing, and return prior results on repeated commands. Persist mutation evidence and receipts transactionally at database-owned mutation seams, never by holding a synchronous SQLite transaction across asynchronous model/kernel work. Interrupted or unsupported mutations are explicitly uncertain, never silently replayed. Existing result consumers retain their result shape. Scope includes database schema/generated migrations, action contracts/execution, drawing/toolpath repositories and a sidecar command module.
3. **Engineering ledger (WP8/WP4).** The existing context module gains a bounded, authorized ledger of requirements, units, drawing/setup/program identities, source revisions, pending work and verification freshness. Include it through the pinned host's compaction hook and specialist briefs. Summaries do not create authoritative facts. Missing or stale evidence is explicit. Scope includes context, compaction prompt, a sidecar evidence builder and runtime mod publication.
4. **Engineering acceptance (WP8/WP3/WP4).** Preserve native goal accounting and expose a separate revision-bound engineering acceptance verdict through existing session controls. The model's completion status does not certify geometry or NC. Provide a budgeted request-to-acceptance evaluation runner using the actual chat seam; no live model run is implied. Scope includes acceptance/goal modules, shared session-control contract and sidecar evidence integration.
5. **Engineering checkpoints (WP11/WP4/WP3/WP8).** Extend existing project history rather than introducing a second snapshot store. Checkpoints link session/task lineage to snapshots of drawings, component state, toolpaths and referenced libraries. Creating a checkpoint does not move the checked-out branch. Restore is explicit and revision-checked, restores related domain state coherently and invalidates stale CAM evidence. Conversation-only fork must not imply isolated document edits. Scope includes project VCS module/repository, existing AI VCS actions/contracts and their prompts.
6. **Embedded host compatibility (WP8).** Keep version-specific behavior in the existing adapter. Publish a capability manifest of methods/hooks actually checked against sdk-next 1.428.0; validate required methods during host bootstrap and report a typed compatibility failure. Preserve mandatory patch-marker and isolated packaged-host checks. CLI restart hooks are not assumed to exist in the embedded host.

Shared integration files are owned by the root agent: `packages/ai/src/index.ts`, `nikcli/runtime.ts`, `nikcli/sdk-next.d.ts`, `service.ts`; `apps/sidecar/src/services/ai.ts`, `acting-user.ts`, `http/ai.ts`; `packages/api/src/groups/ai.ts`; generated clients/reference where needed. Worker agents coordinate additions to these through the root. Existing unrelated changes in `services/workflow-steps.ts` must be preserved.

The standalone nikcli adapter (`packages/nikcli-plugin/src/client.ts`, `index.ts`, WP9) forwards the original session/call identity to the same execution seam. Existing callers may omit it for compatibility; the sidecar assigns a fresh identity in that case and does not claim deduplication across separate legacy HTTP requests.
